# Human Directed Agent Kit

사람이 목표와 중요한 결정을 책임지고, 코딩 에이전트에 범위가 정해진 실행을 맡기기 위한 한국어 지침·스킬 묶음이다. 방법을 관성적으로 고르거나 설명과 실제 구현이 어긋나는 문제를 줄이는 데 초점을 둔다.

Codex 자체가 도구 실행·반복·문맥 관리를 맡는 하네스다. 이 저장소는 그 위에 적용하는 작업 방식이며 새 모델·런타임·MCP·브라우저·외부 서비스를 설치하지 않는다. Markdown 지침은 실행을 강제하는 보안 장치가 아니며 평가 점수·모델 행동을 보장하지 않는다.

## 구성과 설계

| 파일 | 역할 |
| --- | --- |
| [AGENTS.md](AGENTS.md) | 문제 정의·사람의 결정·자율 실행·이해를 연결하는 상시 원칙 |
| [decision-brief](.agents/skills/decision-brief/SKILL.md) | 중요한 방법을 고르기 전 자료·대안·근거 확인과 쉬운 설명 |
| [scoped-build](.agents/skills/scoped-build/SKILL.md) | 범위 안에서 실행을 끝내고 미합의 결정만 사람에게 돌림 |
| [explain-implementation](.agents/skills/explain-implementation/SKILL.md) | 실제 선택·흐름·검증·수정 이력을 작업 중 기록하고 자기 설명을 돕기 |
| [build-web-service](.agents/skills/build-web-service/SKILL.md) | 사용자 흐름·API·필요한 저장소·오류 표시를 연결해 구현·검증 |
| [install.py](install.py) | 프로젝트 안에 스킬 복사, 선택적으로 기존 AGENTS 뒤에 지침 추가 |
| [TEAM.md](TEAM.md) · [team.py](team.py) | 수동 CLI 사이의 로컬 작업 배정·결과 수집. 에이전트가 대기·실행·보고를 반복 |
| [연습 과제](practice/BRIEF.md) | 직접 만든 CSV로 관측·정책·구현·이해를 구분하는 연습 |

중요한 선택에서는 기존 자료와 원문을 먼저 확인하고 현실적 대안을 비교한다. 조사가 선택을 바꾸지 않는 반복 구현은 바로 진행한다. 모든 선택마다 폭넓은 검색을 강제하면 구현과 검증 시간이 줄어들 수 있어 이렇게 구분했다.

사람에게 돌릴 경계는 주관성·작업 길이보다 **목표·데이터 의미·오류 비용·수용 기준을 바꾸는 미합의 선택인지**로 판단한다. 예를 들어 결측 개수 세기는 자율 관측이며, 결측 행 제거가 분석 대상을 바꾸면 정책 선택이다. 기존 합의가 답을 정하면 반복 승인 없이 실행한다.

설명은 먼저 쉬운 말과 실제 사례로 제공하고, 중요한 선택에서 대안·근거·한계를 충분히 연결한다. 사람의 이해와 결정은 지침 파일로 대신할 수 없다. 모르는 내용을 질문하고 결과를 확인하는 사용자 참여가 필요하다.

## 적용 전

현재 프로젝트의 안내·허용 도구·기존 AGENTS를 먼저 읽는다. 제한된 환경에서는 그 환경의 설치 지침을 따른다. 명시된 공개 자료 허용 범위 안에서는 가져오기·읽기 같은 일상 작업에 임의의 추가 승인 절차를 만들지 않는다. 이 저장소의 용도와 작성 시점을 숨기거나 공개 자료 허용을 다른 AI·문제 외부 전송·관리 설정 변경의 허용으로 확대하지 않는다.

이 묶음에는 실제 시험 문제·안내문·모범 답안·사용자 비공개 설정을 넣지 않는다. 외부 전송과 외부 AI가 제한된 작업에서는 그 제한을 그대로 지킨다.

## 관리되는 환경: 파일을 읽어서 적용

기존 프로젝트 안내와 관리 지침을 먼저 읽는다. 전역 적용을 위해 Codex 홈의 AGENTS·override·설정·심볼릭 링크를 변경하지 않는다. 원본 지침을 복사해 override에 포함해도 지침을 발견하는 우선순위는 달라질 수 있다.

제공 Codex에 아래처럼 요청할 수 있다. 실제 프로젝트 폴더와 허용 범위에 맞춰 실행한다.

```text
https://github.com/gam5247/human-directed-agent-kit.git 을 프로젝트 안 _agent_kit에 가져와줘.
이미 있으면 원격·브랜치·변경 상태를 먼저 확인하고 로컬 변경을 보존해줘.
깨끗한 기존 사본의 업데이트는 fast-forward로만 하고 임의 reset이나 덮어쓰기는 하지 마.
기존 과제·관리 지침을 우선하면서 _agent_kit/AGENTS.md를 읽고 적용해줘.
필요한 스킬은 그 파일 위치를 기준으로 실제 SKILL.md를 찾아 읽어줘. 전역 설정은 바꾸지 마.
과제·데이터에서 필수조건과 현재 할 일을 정리한 뒤 실제 입력의 대표 흐름부터 완성해줘.
문서화와 핵심 복습·예상 질문은 작업 중 알아서 준비하고, 중요한 판단만 추천안과 함께 물어봐.
```

이 방식은 프로젝트 파일 읽기이며 자동 스킬 등록은 아니다. 하위 폴더에 clone만 해두는 것으로 프로젝트 루트 세션에 지침이 자동 적용되지 않는다. 새 CLI 세션에서도 같은 경로와 현재 합의를 읽게 한다. 작업 지침은 모델 행동을 유도하며 강제 장치는 아니다.

여러 세션으로 일할 때는 파일·인터페이스·DB 스키마·실행 포트를 나눈다. 브라우저 확인용 서버는 별도 터미널에 유지하고 같은 포트에 중복 서버를 띄우지 않는다. 에이전트의 완료 보고와 실제 화면 확인을 구분한다.

복사 중계 없이 총괄과 작업자가 협업하려면 [TEAM.md](TEAM.md)를 따른다. 총괄만 clone·초기화하고 작업자는 고유 ID로 `team.py wait`를 반복해 배정을 받는다. 결과는 `finish`, 총괄 수집은 `status`다. 같은 프로젝트 루트·활성 CLI 턴이 필요하며 종료된 CLI를 깨우는 런처는 아니다. 우편함은 프로젝트 로컬 `.agent-team/`에만 둔다. 기본 스킬 설치는 이 도구를 복사하지 않으므로 clone한 사본의 `team.py`를 사용한다.

## 프로젝트 스킬 설치: 허용된 프로젝트에서만

자신이 관리하는 프로젝트에서 스킬 자동 발견이 필요하면 설치기를 사용할 수 있다. Git과 Python 3.9 이상이 필요하고 외부 Python 패키지는 필요하지 않다. Linux에서는 보통 `python3`, Windows에서는 사용 가능한 `python` 또는 `py -3`를 사용한다.

프로젝트 루트의 **셸**에서 실행한다. 기존 clone에 로컬 변경이 있으면 덮어쓰지 않는다.

```sh
git clone https://github.com/gam5247/human-directed-agent-kit.git _agent_kit
python3 _agent_kit/install.py --target . --dry-run
python3 _agent_kit/install.py --target .
codex
```

기본 설치는 스킬만 복사한다. `--dry-run`은 변경 경로만 보여준다. 프로젝트 지침 수정까지 허용되고 필요할 때만 `--with-agents`로 기존 AGENTS 뒤에 전용 구간을 덧붙인다. 관리 지침을 대상으로 사용하지 않는다. 과제 루트가 사용자 홈 자체라면 전역 발견 범위와 겹칠 수 있으므로 위의 파일 참조 방식을 우선한다.

기존의 다른 동명 스킬, 손상된 표시 구간, 루트의 `AGENTS.override.md`, 프로젝트 밖으로 이어지는 쓰기 경로, Codex 전역 설정 디렉터리를 대상으로 삼은 설치는 중단한다. 같은 구성을 재설치해도 중복 추가하지 않는다. 다른 버전의 스킬이 이미 있으면 자동 덮어쓰지 않으므로 파일 참조 방식으로 사용하거나 일반 개발 환경에서 차이를 검토한다.

설치기는 전역 설정·인증·권한·감독 설정을 변경하거나 네트워크에 접속하지 않는다. 실행 중 I/O 오류가 발생하면 일부 파일만 복사됐을 수 있으므로 출력과 파일을 확인한다.

AGENTS 자동 발견은 일반적으로 세션 시작 때 이루어진다. 설치 후 새로 시작하거나 파일을 명시적으로 읽게 한다. 스킬이 발견되면 **Codex 입력창**에서 `$decision-brief`, `$scoped-build`, `$explain-implementation`, `$build-web-service`로 필요한 것을 호출한다. 발견되지 않으면 설정을 바꾸기보다 실제 `SKILL.md` 경로를 지정해 읽게 한다.

## 사람이 익힐 원칙

1. 기술보다 먼저 사용자 문제·성공 조건·손해를 이해한다.
2. 중요한 선택은 근거·대안·한계를 보고 정한다. 특정 언어·모델을 고정 정답으로 외우지 않는다.
3. 정해진 구현은 맡기고, 의미가 바뀌는 결정에서 방향을 확인한다.
4. 설명은 실제 코드와 입력·출력으로 확인한다. 주장한 성능에는 그 주장에 맞는 측정이 필요하다.
5. 중요한 선택 이유와 실패 조건을 자기 말로 설명한다. AI가 대신 쓴 답변을 자신의 판단 이력으로 삼지 않는다.

## 작업 중 기록하고 자기 말로 설명하기

짧게 ‘해줘’라고 요청해도 실제 과제와 기존 합의에서 목표·범위·기본값·검증 기준을 정리하고 진행한다. 문서화·핵심 복습·예상 질문 준비는 자동으로 맡되, 결과의 의미를 바꾸는 미합의 업무 판단은 추천안과 함께 사용자에게 묻는다. 관련 질문은 묶고 독립적인 구현·조사는 계속한다.

실제 입력의 대표 흐름을 먼저 완성하고 필수조건을 유지한다. 조사·구현·검증·설명·제출에 남은 시간을 배분하며, 간단한 작업에 과한 계산 인프라를 도입하지 않는다. 여러 세션은 공유 문서와 통합의 담당까지 정한다.

중요한 선택·대표 흐름·오류 수정이 끝날 때 기존 현행 문서의 관련 부분을 갱신한다. 선택과 대안, 실제 데이터·상태 흐름, 관측한 입출력, 실패·변경 조건, 미확인 부분, 다음 작업이 연결돼 있어야 한다. 이미 문서 역할이 있으면 그대로 쓰고, 작은 작업은 한 README 안의 짧은 기록으로 충분하다. 여러 세션도 하나의 현행 상태를 공유한다.

세부 기준은 [explain-implementation](.agents/skills/explain-implementation/SKILL.md)에 있다. 낯선 용어와 강한 주장은 실제 근거를 확인하고 설명한다. 제출·인수인계 전에는 도움을 받을 수 있는 단계에서 사용자가 직접 핵심 내용을 설명해 보고 빈 부분만 보충한다. 기록에 근거한 질문이 생겨도 자신의 실제 작업과 연결해 답할 수 있게 하는 방식이며, 질문 생성 방향·난이도·평가 결과를 보장하지 않는다.

대표 흐름이 작동하면 기존 문서에 쉬운 핵심 요약·현재 문서에서 나올 예상 질문·근거 경로를 자동 준비한다. 실제로 이해·확인한 선택과 입출력을 요약 앞쪽에 두고 기본 질문부터 연습한다. 사용자가 답한 뒤 오해를 보충하며 하지 않은 판단이나 개인 답안을 대신 쓰지 않는다. 설명·기록·복습 때문에 매번 구현을 멈추지 않고 연습 수행 여부도 정확히 구분한다.

웹·계산 서비스는 상태 소유와 긴 작업의 재실행·실패·공개 규칙을, 최적화는 제약 충족과 개선·최적성의 차이를 확인한다. 조사·비교·변경 검토는 출처·기간·단위·판단 기준과 가정의 영향을 연결한다. 특정 기술 구조나 많은 문서가 필수인 것은 아니다. 계획을 구현으로, AI 보고를 실제 관측으로, AI가 정한 이유를 사용자 판단으로 바꾸어 쓰지 않는다.

## 확인 범위

수동 CLI용 `team.py`를 추가했다. 별도 CLI 프로세스가 같은 작업자 ID로 동시에 요청했을 때 한 프로세스만 작업을 받았고 다른 프로세스는 busy를 받았다. 활성 경로의 중복 배정·잘못된 완료 token·취소 뒤의 늦은 보고는 거절됐고, 정상 결과는 총괄의 status에서 읽혔다. 이는 로컬 명령·저장소 통신의 검증이며 실제 Cofa의 여러 Codex 세션을 장시간 실행한 결과는 아니다. 이미 끝난 CLI 턴을 자동으로 깨우는 기능은 없다.

같은 날 현장 운영을 다시 검토해 현재 사본의 스킬 경로, 짧은 요청의 범위 정리, 필수 흐름·마감 우선, 자동 복습과 설명 중복을 보완했다. 새 로컬 프로젝트에서 기존 AGENTS 원문을 보존하고, 설치된 설명 스킬에 자동 복습 준비 절이 포함되는 것을 확인했다. 스킬 형식도 검사했다. ‘해줘’, 분석·변경 검토, 마감 직전 상황은 지침을 요청 사례에 대입해 검토한 것이며 별도 모델로 실제 작업을 실행한 검증은 아니다.

2026-11-05, 작업 중 사실 기록·현행 핸드오프·자기 설명을 보완했다. 공개용 사본의 설치기를 새 로컬 프로젝트에 적용했을 때 기존 AGENTS의 BOM·CRLF와 원문 접두부가 보존됐고, 설치된 설명 스킬에 새 기록 기준이 들어간 것을 확인했다. 네 스킬 모두 갱신한 원본과 같은 내용으로 설치됐다. 기존 설치 확인에서도 파일 충돌·관리 설정 대상 거절 동작을 유지했다. 이 확인은 파일 적용 범위이며, 실제 에이전트의 준수·사용자 이해·질문 생성·평가 효과는 확인하지 않았다.

2026-10-31, Windows의 Python 3.12 환경에서 다음 동작을 확인했다.

- 기존 AGENTS에 BOM·CRLF가 있는 프로젝트에서 원래 바이트를 앞부분에 보존해 덧붙였고, 재설치해도 중복되지 않았다. 미리보기에서는 파일이 바뀌지 않았다.
- 동명 스킬이 다른 내용인 경우, override가 있는 경우, 표시 구간이 손상된 경우에는 다른 파일을 추가하기 전에 멈췄다. 프로젝트 밖을 가리키는 심볼릭 링크로도 외부에 쓰지 않았다.
- 첫 버전을 별도 빈 작업 폴더에 설치한 뒤 로컬 Codex CLI 0.155.0의 `skills/list`에서 `decision-brief`, `scoped-build`, `explain-implementation`이 프로젝트 스킬로 활성화되어 발견됨을 확인했다. 이 확인에는 모델 호출이나 새 작업 에이전트를 사용하지 않았다.
- 공개 GitHub 저장소를 자격 증명 없이 새로 clone하고, 그 사본의 설치기로 빈 프로젝트에 지침과 스킬을 설치했다. 같은 사본의 가상 CSV 점검도 아래와 같은 결과를 냈다.
- 가상 CSV를 실제 읽었을 때 6행·5개 배치, 반복 `A01`, 세 번째 데이터 행의 불량 수 누락, `final` 4행·`revised` 1행·`pending` 1행을 출력했다. 업무상 처리 정책은 적용하지 않았다.
- 스킬 frontmatter·이름은 skill-creator의 검사로 확인했다.

이후 전역 설정 디렉터리를 설치 대상으로 삼지 못하도록 보완하고 웹서비스 스킬·착수 가정 설명·동시 세션 경계를 추가했다. 현재 설치기에서 모의 Codex 홈을 대상으로 삼으면 파일 추가 전에 거부하는 것을 확인했다. 새 빈 프로젝트에 설치한 뒤 로컬 Codex 0.155.0의 `skills/list`에서 `build-web-service`를 포함한 네 스킬이 프로젝트 범위로 활성화되어 발견됐다. 이 확인에도 모델 호출이나 새 작업 에이전트를 사용하지 않았다.

위 결과는 로컬 설치·발견·파일 실행의 범위다. 모델이 지침을 항상 따르는지, 사용자에게 실제로 학습 효과가 있는지, 특정 평가에서 점수가 오르는지, 현재 개선판이 다른 제한 환경에서 허용·실행되는지는 확인하지 않았다. 현재 개선판을 Linux에서 실제 실행한 결과도 아직 없다.
