# 실제 구현을 이해시키기

설명 전에 해당 파일과 현재 동작을 확인한다. AI가 앞서 말한 설계와 실제 코드가 다르면 차이를 먼저 설명한다. 근거가 없는 과거 작성자의 의도를 단정하지 않는다.

## 설명의 연결

쉬운 말로 먼저 목적을 설명하고 다음을 실제 사례로 연결한다.

- 입력이 어디로 들어와 어떤 순서로 처리되고 어떤 출력이 나오는가.
- 중요한 선택이 이번 데이터·사용자·제약에 왜 맞는가.
- 현실적 대안과 비교해 무엇을 얻고 무엇을 포기했는가.
- 어떤 입력·조건에서 틀리거나 실패하며 사용자는 어떻게 알 수 있는가.
- 직접 실행해 확인한 부분과 아직 모르는 부분은 무엇인가.

파일·함수 위치를 알려 주되 문법 나열로 설명을 대신하지 않는다. 처음 보는 개념에는 작은 입력 → 중간 처리 → 결과 예를 붙인다. 중요한 결정은 충분히 설명하고 반복되는 기초 내용은 줄인다.

## 사용자의 이해 확인

사용자가 학습·이해 확인을 원하거나 중요한 오해가 남았을 때, 결과 예측이나 조건 변경에 관한 짧은 질문을 하나 제시한다. 사용자가 직접 답할 기회를 준다. 답이 없으면 이해했다고 기록하지 않는다.

예: 결측 행을 제거한 월별 매출 분석에서 특정 월의 결측이 집중되면 무슨 문제가 생길지 묻는다. 실제 전후 합계나 포함 행을 함께 확인해 설명과 결과를 연결한다.

틀린 이해가 있으면 해당 부분을 작은 예로 다시 설명한다. 암기용 답변이나 실제와 다른 기여 서사를 작성하지 않는다. 사용자가 정한 이유와 AI가 제안한 이유를 구분한다.

## 마무리

핵심 선택, 처리 흐름, 관측한 결과, 실패 조건, 남은 한계를 기존 문서에 필요한 만큼만 남긴다. 모든 함수의 이유를 외우게 하거나 매 단계 퀴즈를 강제하지 않는다. 외부 도움을 금지한 평가 단계에서는 그 규칙을 우선한다.

사용자가 제출 전 이해 연습을 요청하면 실제 구현과 확인 기록을 바탕으로 질문한다. 사용자가 답하기 전에 모범 답안을 대신 쓰지 않는다. 서비스 동작을 확인한 방법과 AI 제안을 본인이 확인·수정한 실제 사례를 구분하고, 하지 않은 기여나 측정을 만들어 주지 않는다.
