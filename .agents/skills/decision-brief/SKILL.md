# 방법 선택과 근거 설명

## 먼저 확인할 것

요청·기존 지침·현행 문서·코드와 데이터에서 목표와 제약을 확인한다. 아직 모르는 내용을 구체화하고, 그 정보가 선택을 바꿀 때만 질문하거나 조사한다. 결과물이 무엇인지 모르는데 기술부터 정하지 않는다.

## 비교의 깊이

- 처음 하는 중요한 선택: 가능한 방법의 종류를 넓게 훑고, 단순한 기준선과 성격이 다른 현실적 대안을 남긴다. 형식적으로 선택지를 채우지 않는다.
- 익숙한 기존 구조의 작은 변경: 저장소 구현·테스트·공식 API 문서 등 직접 관련 근거면 충분하다.
- 불확실성·실패 비용이 큰 선택: 상충하는 근거와 실패 사례까지 확인하고, 가능하면 작은 비교 실험으로 결론을 좁힌다.

검색은 풀려는 질문으로 시작한다. 결과 요약만 인용하지 말고 실제 원문·공식 문서·논문·공개 구현을 확인한다. 기존 문서가 답을 주면 다시 검색하지 않는다. 외부 자료를 볼 수 없으면 그 한계를 밝히고 확인 가능한 단순한 안으로 진행할 수 있는지 판단한다.

## 사용자가 이해할 설명

중요한 선택에 대해 다음 내용이 연결되게 설명한다. 고정 양식을 길게 채우는 것이 목적은 아니다.

1. 해결할 문제와 선택이 중요한 이유.
2. 실제 데이터·환경에서 확인한 사실과 아직 미확인인 가정.
3. 현실적인 대안별 정확성·시간·비용·복잡성·실패 위험의 손익.
4. 추천안이 이번 조건에 맞는 이유와 다른 안을 고르지 않은 이유.
5. 어떤 조건이면 추천이 바뀌는지, 무엇을 실행해 확인할지.

빠른 구현을 위한 단순화라면 무엇을 고정하고 무엇만 바꾸는지, 그 때문에 놓치는 선택이 무엇인지 밝힌다. 복잡한 대안의 개발을 계속하기 전에 구현·검증·설명 시간을 남기는 중단 기준을 정한다. 현재 동작하는 기준선을 유지하고, 미완성 대안을 완료된 성능 개선으로 기록하지 않는다.

새 기술어는 쉬운 뜻과 작은 예를 함께 설명한다. 자료의 주장, 자신의 추론, 직접 측정을 구분하고 확인한 원문 링크를 붙인다. 출처가 많다는 사실을 우수성의 근거로 삼지 않는다.

## 데이터·모델 선택 시

- 분석·규칙·검색·예측 중 무엇이 필요한지부터 판단한다. 예측이 필요하지 않은 문제에 모델을 먼저 붙이지 않는다.
- 예측이면 목표 변수·실제 추론 시점에 이용 가능한 정보·평가 지표·분할 단위를 먼저 확인한다. 미래 정보·동일 개체·중복 입력이 학습과 평가에 섞이는지 본다.
- 결측·중복·이상값·라벨·재측정은 먼저 분포와 실제 행을 관측한다. 제거·대체·통합이 모집단이나 결과를 바꾸면 정책 선택으로 설명한다. 전처리는 의미에 따라 모델 선택만큼 중요한 결정일 수 있다.
- 단순 기준선과 비교한 관측이 없으면 특정 모델·언어·패키지가 더 우수하다고 결론 내리지 않는다. 최종 평가 자료에 반복 맞추지 않는다.

## 최적화·분석·검토 과제라면

- 목적함수나 비교 기준과 반드시 지켜야 하는 제약을 나눈다. 실행 가능한 해, 기준선보다 좋은 해, 최적성이 증명된 해를 구분한다. 시간 제한 종료·탐색 중단·해 없음·입력 오류도 서로 다른 결과다.
- 결과 생성과 별개인 확인 경로로 누락·중복·제약·합계를 원래 입력에 대조한다. 생성기의 같은 중간값을 다시 읽거나 AI 설명을 반복하는 것만으로 독립 검증이라고 부르지 않는다. 유효한 결과라는 사실만으로 전역 최적성을 주장하지 않는다.
- 중요한 조건을 강화·완화하거나 데이터 일부를 바꿨을 때 예상 변화와 유지돼야 할 조건을 먼저 정한다. 불가능해진 문제를 오류 없이 성공한 것처럼 보이게 하지 않는다. 실행하지 않은 조건은 미확인으로 남긴다.
- 조사·성과 비교에서는 출처, 기준일·대상 기간, 대상 범위, 단위, 분모와 계산식을 확인한다. 확인된 실적, 전망, 가정, 해석을 구분하고 서로 다른 기준의 숫자를 그대로 비교하지 않는다.
- 대안 선정·변경 검토에서는 통과해야 할 필수조건과 선호도를 나눈다. 비용·품질·공급 안정성 등 실제 업무의 손익, 빠진 정보, 적용 범위와 되돌릴 조건을 연결한다. 임의 가중치나 결측값을 업무상 확정 기준으로 만들지 않는다.

## 결정하고 실행하기

선택을 `기존 합의로 결정`, `AI가 범위 안에서 선택`, `사용자 결정 필요` 중 실제 상황에 맞게 설명한다. 새 사용자 결정이 필요하면 근거와 추천을 제시하고 해당 작업만 기다린다. 이미 위임된 기술 선택은 이유를 알리고 진행한다.

중요한 선택은 기존 현행 문서에 문제·선택 이유·확인 방법·결정 주체를 짧게 남긴다. 근거 없는 사용자 동의나 사후에 만들어 낸 선택 이유를 기록하지 않는다.
